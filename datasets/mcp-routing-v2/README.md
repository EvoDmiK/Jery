# 전체 MCP 분류용 합성 데이터셋 v2

한국어 요청과 이전 대화, 후보 도구 명세를 보고 **다음 MCP 서버·도구**를 선택하는 초기 학습 자료다. 실제 Hermes 대화·호출·실행 결과를 사용하지 않았다. 모든 정답은 명세 기반 초안이며 `needs_human_review`, `execution_verified: false`다.

## 대상과 출처

2026-10-16에 활성 Hermes `hybrid-v2`의 `config.yaml`에서 **서버 이름만** 대조했다. 인증 정보와 환경 변수 값은 가져오지 않았다.

| 서버 | 도구 수 | 범위 |
|---|---:|---|
| grafana | 62 | 대시보드, 데이터소스, Prometheus·Loki·Tempo·Pyroscope, 알림, OnCall 등 |
| korean_law | 10 | 법령 검색·조문·별표, 법률 리서치·분석, 전문 도구 탐색·실행 |
| obsidian_vault | 10 | 기본 도구 8개와 MCP 리소스 유틸리티 2개 |
| swallow_trader | 13 | 시세·뉴스·포트폴리오, 가상 주문·초기화, 관심종목, 백테스트 등 |
| kestrel | 1 | Codex 리셋 이벤트·상태 조회 |
| **합계** | **96** | **등록 서버 5개** |

4개 서버의 도구는 로컬 `mcp_schema_cache.json`에서 추출했다. Grafana는 캐시에 없어 등록 설정의 `mcp-grafana==2.0.0 --disable-write`에 맞춰 공식 배포본을 별도로 실행했다. 외부 Grafana에 접근할 수 없는 로컬 대체 주소, 가짜 인증 값, 사용 통계 비활성화 환경에서 MCP `initialize`, `notifications/initialized`, `tools/list`만 수행했다. `tools/call`, 실제 사용자 데이터 조회와 Hermes 실행은 수행하지 않았다.

Grafana 출처는 [고정 버전 공식 배포](https://pypi.org/project/mcp-grafana/2.0.0/)이며, 배포 파일의 SHA-256을 검증했다. 배포 URL·버전·해시·읽기 전용 플래그를 `tools.json`의 `sources`에 기록했다. 패키지는 Apache-2.0 라이선스다. 나머지 서버는 저장된 캐시의 명세이므로 실제 서버 최신 버전과 다를 수 있다. 전체 도구는 **등록 설정과 확보한 명세 기준**이며 실제 연결 성공을 뜻하지 않는다. Grafana의 쓰기 도구, 한국 법률 서버 내부의 비노출 전문 도구는 별도 클래스로 부풀리지 않았다.

## 파일과 사용

- `tools.json`: 카탈로그 `hermes-mcp-57e701d87790`, 서버·도구 이름, 실제 설명과 입력 스키마, 출처.
- `labels.json`: 정답 도구 ID → MCP 서버, 도구 종류, action enum의 매핑.
- `scenarios.json`: 사람이 읽고 수정할 수 있는 합성 요청·맥락·정답 초안, 시나리오 그룹과 분할. 재생성의 입력이다.
- `train.jsonl`, `validation.jsonl`, `test.jsonl`: 기존 routing 행 형식의 모델 학습·검증·평가 자료.
- `manifest.json`: 데이터 버전 `mcp-routing-v2`, 건수·분포·시드와 SHA-256.

모델 입력에는 `request`, `context`, `candidate_tools`에 해당하는 카탈로그 명세만 사용한다. `id`, `scenario_id`, `split`, `acceptable_choices`, 검토 상태와 출처는 특징으로 사용하지 않는다. 특히 ID에는 도구명이 포함되어 있어 정답 누출을 일으킨다.

출력 라벨 `acceptable_choices`의 `tool`을 예측한다. 서버 라벨은 `tools.json` 또는 `labels.json`으로 도구 ID에서 얻는다. 여러 정답은 허용되는 **대안**이지 실행 단계가 아니다. 단일 종목 보유 현황처럼 전용 조회와 시세 조회가 모두 가능한 사례는 대안을 함께 기록했다. action은 명세에 있는 값만 보조 라벨로 사용하며, `mode`·`operation` 등 다른 인자 생성은 현재 범위가 아니다.

## 구성

1,162개 사례, 시나리오 그룹 340개다.

| 분할 | 사례 | 정답으로 나타나는 도구 |
|---|---:|---:|
| train | 668 | 96 |
| validation | 248 | 85 |
| test | 246 | 84 |

결정 유형은 `select_tools` 1,062개, `unsupported` 60개, `no_tool` 20개, `clarify` 20개다.

각 시나리오에 전체 96개 후보와 일부 후보 버전을 만든다. 일부 후보에는 정답과 같은 MCP의 헷갈리는 도구 및 다른 MCP 도구를 함께 넣는다. Swallow의 초기화·수동 주문·파이프라인·관심종목 시나리오는 지원 도구가 빠진 버전도 포함한다. 이 경우에만 해당 요청을 `unsupported`로 바꾼다. 기능이 있는 전체 카탈로그만으로 정답을 정하지 않는다.

`그 종목 현재가 조회해줘`처럼 맥락이 없으면 `clarify`, 선행 대화로 종목이 정해졌으면 도구 선택인 짝도 포함한다. 같은 요청의 문맥 유무, 후보 변형, 표현 변형은 같은 그룹과 분할을 유지한다. 무인자 초기화·리소스 목록 등 사실상 같은 요청의 여러 표현은 학습에 묶었으므로 모든 도구가 검증·평가에 나타나지는 않는다. 미등장 클래스의 평가 수치를 전체 96개 클래스 성능으로 주장하면 안 된다.

## 재생성과 검증

Python 3 표준 라이브러리만 사용한다. 네트워크와 Hermes 없이 실행한다.

```sh
python3 scripts/build_mcp_dataset.py
python3 scripts/validate_mcp_dataset.py
python3 -m unittest discover -s tests/data -v
```

빌더는 저장된 `tools.json`, `scenarios.json`으로 v2의 분할·라벨 맵·manifest를 재생성한다. v1 빌더를 호출하거나 `hermes-routing-v1`을 변경하지 않는다. 다른 출력 디렉터리에서 작업하려면 두 입력 파일을 먼저 복사한 뒤 `--directory PATH`를 지정한다. 분할 시드와 후보·행 순서는 결정적이다.

검증기는 서버·도구·action 참조, 후보 밖 정답, 그룹 분할 누출, 중복·상충 입력, 도구 커버리지, 클래스 분포와 체크섬을 확인한다. 테스트는 같은 입력의 바이트 단위 재생성, 잘못된 후보·action·서버 라벨, 파일 변조와 그룹 누출 거부를 확인한다.

## v1 관계와 한계

기존 v1의 행 필드와 결정 의미를 유지하며 데이터·카탈로그를 별도 버전으로 확장했다. v1의 도구 10개에 대한 시나리오를 재사용하되, v1에서 `unsupported`였던 Swallow 주문·초기화는 새 카탈로그에서는 지원한다. v1 라벨을 전체 카탈로그에 그대로 적용하면 안 된다. v1과 v2를 단순 합치면 같은 요청의 중복과 분할 누출이 생길 수 있으므로 둘 중 하나를 선택해 실험한다.

도구별 사례 수가 적고 불균형하며 같은 기능군·표현 패턴이 분할 간 반복된다. 동작 중인 도구를 통해 정답을 검증하거나 사람이 전체를 검토하지 않았다. 합성 법령·결정·대시보드·리소스 식별자는 실제 존재를 보장하지 않는다. 법률 요청은 라우팅 예시이며 법률 사실을 주장하지 않는다. 전체 도구 클래스는 포함하지만 모든 action·인자 조합이나 실제 요청 분포를 망라하지 않는다.

기준 모델을 위한 탐색 자료이며 실제 사용 정확도 측정에는 별도로 검토한 실제 요청 평가셋이 필요하다. 다음 작업은 정답 검토와 기준 모델 실험이다. 실험에는 이 데이터 버전·카탈로그 버전과 해당 분할에서 평가 가능한 클래스 수를 함께 기록한다.
